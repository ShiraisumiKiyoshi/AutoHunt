## 一、UI 现代化改造

### 1.1 现状问题

- 界面是纯 ImGui 平铺控件，无分组、无视觉层次
- 「基本」「招募」「跨区」三页都有大量开关 + 滑条堆叠，密度高、找配置困难
- 车头信息是一行小字，与「状态」页重复且无操作入口（只有"取消车头"一个按钮）
- 状态信息（狩猎状态 / 副本区 / 击杀数）是纯文本，扫一眼抓不到重点

### 1.2 改造目标

不换 UI 框架（仍是 Dalamud ImGui），通过**布局重组 + 卡片化 + 状态着色**实现现代化，交互层级变浅。全部用原生 ImGui / ECommons 实现，不引入新依赖，渲染性能不变。

### 1.3 新布局


### 1.4 「当前执行操作」实时显示（新增需求）

设置窗口任何页面都能一眼看到插件**此刻正在做什么**。现状是各流程状态分散（狩猎状态只在"状态"页、跨区状态只在"跨区"页、招募/切区完全没有显示），需要在主窗口顶部新增一条**全宽当前操作条**。

**实现方案**：新建状态汇聚器 `OperationTracker`（静态类，无轮询开销，直接读各控制器现有状态）：

| 优先级 | 来源 | 示例显示 |
|--------|------|----------|
| 1（最高） | 跨区流程 `CrossRegionController.CurrentState` | `跨区 — 传送到跨区后水晶` |
| 2 | 副本区切换（`SwitchInProgress` / 切区任务执行中） | `副本区切换 — 传送中（目标 2 号区）` |
| 3 | 自动获取车头 `ConductorFetchService` | `获取车头 — 读取招募列表（已获取 3 个）` |
| 4 | 招募创建任务链（`TaskManager.IsBusy` 且无其他来源） | `创建队员招募…` |
| 5 | 狩猎流程 `HuntController.CurrentState` | `狩猎 — 下降中（目标 [A] 怪名）`、`狩猎 — 输出中（血量 45%）` |
| 6 | 寻路/传送中（vnavmesh 路径进行中、`TeleportTo` 等待到达） | `移动 — 飞向坐标 (12.3, 45.6)` |
| 7（空闲） | 以上均无 | `空闲 — 等待车头坐标` |

**显示规则**：

- 按优先级取**最高优先级的活动操作**显示（跨区进行时优先于狩猎状态，因为跨区已中止狩猎）
- 操作条配色按类别：跨区=紫、切区=黄、获取车头=青、招募=蓝、狩猎=绿、空闲=灰
- 跨区流程在操作条右侧附加**阶段进度指示**（`解散小队 → 传送城市 → 跨区 → 传送水晶 → 获取车头 → 开招募`，已完成阶段打勾）
- 状态页不再重复显示单独的"当前状态"行，改为完整流程明细（含中间过程、耗时、超时倒计时）
- 操作条每帧从各控制器现有属性读取（全部是 `CurrentState` 这类廉价属性），无性能影响

### 1.5 交互简化

- 每个卡片<u>标题右侧加 </u>**<u>折叠箭头</u>**<u>（`ImGui.TreeNode` 风格），高级参数默认收起（如"狩猎流程参数"）</u>
- <u>滑条统一带</u>**<u>当前值显示</u>**<u>与 tooltip（现状部分有部分没有，补齐）</u>
- <u>所有开关即时保存（保持现状 `EzConfig.Save()`），但</u>保存失败时聊天提示
- 指标卡可点击：点"狩猎状态"卡切到状态页，点"跨区流程"卡切到跨区页

## 二、多车头 + 自动获取车头

### 2.1 数据结构改造（核心）

现状：车头是**单个名字**（`Config.ConductorName` + `ConductorWorldId`），聊天监听只匹配一个名字。

改造为**车头列表**：

```csharp
public class ConductorEntry
{
    public string Name = "";      // 角色名（不带 @世界服 后缀）
    public uint WorldId = 0;      // 所属世界 ID，0=不校验
}

// Config.cs 新增（旧字段自动迁移后废弃）
public List<ConductorEntry> Conductors = new();
```

- **旧配置迁移**：加载时若旧 `ConductorName` 非空且新列表为空 → 自动转为列表第一项，旧字段保留但不再使用（下次保存后从配置文件移除）
- **改动文件**：`Conductor.cs`（核心 API）、`ChatMessageHandler.cs`（发送者匹配）、`ContextMenuManager.cs`（右键菜单）、`MainWindow.cs`（显示与操作）

### 2.2 Conductor 类新 API

| 方法                                     | 行为                                                     |
| -------------------------------------- | ------------------------------------------------------ |
| `IsValid`                              | 列表非空即有效                                                |
| `IsConductor(senderName, senderWorld)` | 聊天匹配：名字命中任一条目（保留现有"@后缀剥离、自己即车头"逻辑，改为遍历列表）；世界服校验按条目独立进行 |
| `Add(name, worldId)`                   | 追加（同名去重），保存并提示                                         |
| `Remove(name)`                         | 移除指定车头（列表清空时**触发跨区衔接**，见 2.4）                          |
| `ClearAll()`                           | 移除全部车头（等价于现在的"取消车头"）                                   |
| `FindNearest()`                        | 返回对象表中距离最近的车头（焦点恢复用）                                   |

### 2.3 聊天监听与焦点保持规则

- **坐标监听**：任一车头发送坐标都触发狩猎流程（匹配逻辑与现在一致，从"比一个名字"改为"遍历列表"）
- **焦点保持**：当前焦点是车头之一 → 保持不动；焦点丢失/被顶 → 自动焦点到**对象表中最近的在线车头**（延续现有 500ms 节流与"绝不动选中目标"的规则）

### 2.4 取消车头与跨区的衔接（行为变化，注意）

现状：`Conductor.Clear()` 在**跨区功能开启**时自动启动跨区流程。

多车头规则：**只有当列表从非空变为空时**才触发跨区衔接。即：

- 单独移除某一个车头（还剩其他车头）→ 只移除，不触发跨区
- "全部取消车头" / 移除最后一个车头 → 触发（与现状一致）

### 2.5 自动获取车头按钮

**入口**：设置窗口主操作按钮区「自动获取车头」。

**流程**（TaskManager 任务链，参照 `TaskCreateHuntPF` 的实现方式）：

1. 校验：角色可用、无任务执行中
2. `/pfinder` 打开招募面板
3. 切换浏览类别为「全部」，打开搜索条件 → 讨伐目标选「怪物狩猎」→ 执行搜索
4. 读取搜索结果中**全部招募条目的招募人名字**
5. 去重后写入车头列表（规则见下方决策点 1/2）
6. 聊天栏提示结果：「已获取 N 个车头：甲、乙、丙…」
7. 关闭招募面板

**实现说明与风险**：

- 招募条目招募人名字的读取通道有两条：① `AgentLookingForGroup` 内部数据（结构体直读，稳定）；② 招募面板 Addon 节点文本解析（兜底）。**节点索引需要游戏内联调确认**，这是本项唯一不确定点，预留一轮调试
- 搜索条件窗口的 Callback 编号参照招募创建任务链已验证的做法（直接操作 NodeList），风险可控

### 2.6 设置窗口车头卡片（新 UI）

```
┌─ 车头（3）──────────────────────────────┐
│  ● 甲同学（陆行鸟）              [取消]   │
│  ● 乙同学（陆行鸟）              [取消]   │
│  ○ 丙同学（未在附近）            [取消]   │   ● 在线/对象表中  ○ 不在附近
├──────────────────────────────────────────┤
│  [自动获取车头]  [+ 手动添加]  [全部取消] │
└──────────────────────────────────────────┘
```

- 状态页同步改为车头列表展示（每行：在线状态点 + 名字 + 所属服务器 + 焦点状态）
- 右键聊天框玩家名「设为车头」改为**追加**（已存在则提示）；菜单中已是车头的玩家显示「取消车头」= 移除该玩家

## 三、跨区：自动获取车头开关

- 「跨区」标签新增开关：**跨区完成后自动获取车头**
- 跨区状态机新增阶段 `FetchConductors`，插入位置：

```
现有：  解散小队 → 传送城市 → 跨区传送 → 传送跨区后水晶 → 自动开启招募
改为：  解散小队 → 传送城市 → 跨区传送 → 传送跨区后水晶 → 【自动获取车头】 → 自动开启招募
                                                （未选水晶/传送失败时同样执行）
```

- 执行的就是第二节「自动获取车头」任务链；失败（面板打不开 / 无结果）时**提示并继续**后续流程，不中断跨区
- 状态页跨区流程状态文案同步：`获取车头中…`

## 四、跨区：自动取消车头 + 结束地图

### 4.1 新配置

| 配置项                              | 类型   | 说明                                          |
| -------------------------------- | ---- | ------------------------------------------- |
| `CrossRegionAutoCancelConductor` | bool | 自动取消车头开关（默认关）                               |
| `CrossRegionEndAetheryteId`      | uint | 结束地图（下拉选项与「跨区后传送到水晶」**完全相同**：不传送 + 全部可传送水晶） |

- 结束地图选「不传送」时自动取消开关**不生效**，UI 中显示灰字提示「请先选择结束地图」

### 4.2 触发条件（全部满足才触发）

新增监控器 `EndMapWatcher`（挂主循环，每秒检查一次）：

1. 「自动取消车头」开启，且结束地图已选择（非"不传送"）
2. 当前角色所在**地图** = 结束地图水晶所在的地图（按 TerritoryType 比对，同一地图多个水晶视为同一结束地图）
3. 车头列表非空
4. **本区击杀数已满**（即状态页显示 2/2 的时刻）
5. 跨区流程未在运行、招募面板操作未在执行

> **实现细节（重要）**：现在击杀数满时会触发副本区切换并把 `killCount` 清零，"2/2"只在瞬间成立。因此条件 4 使用持久化标志：`击杀数 ≥ 配置值` **或** `存在待切换副本区（pendingSwitchInstance ≠ 0）`，两者任一即为"本区打完"。已确认不可切区地图上击杀数会保持满值，同样能触发。

### 4.3 触发动作

1. 自动**取消全部车头**（聊天提示：「本区击杀已满，已自动取消全部车头」）
2. 若「启用跨区功能」开启 → 自动进入跨区流程（现有 `ClearAll → Begin()` 衔接，无需新逻辑）
3. **防重复**：触发后置"已处理"标志，切换地图 / `/ah reset` 时重置——避免同一地点反复触发

### 4.4 完整使用场景（车头视角闭环）

```
 hunting 中，车头在招募面板挂了怪物狩猎招募
 → 本区击杀 2/2，且当前正是「结束地图」
 → 自动取消全部车头 → 自动跨区到时间表下一服务器
 → 传送至跨区后水晶 → 自动重新获取招募面板中的车头 → 继续狩猎
```
